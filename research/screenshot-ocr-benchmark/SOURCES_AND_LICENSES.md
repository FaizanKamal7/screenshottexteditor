# Phase 0 review: prior work, licenses and provider terms

Status: Phase 0 working document. Retrieved 2026-09-24. Not legal advice; every
"verify" item must be closed before the pilot runs.

Scope rule for this whole project: no user-uploaded images, no analytics data,
no production data. Everything in the benchmark is generated by us or captured
by us on devices we own, from templates we wrote.

---

## 1. Literature and dataset review

Method: web search plus reading the primary pages (dataset homepages, GitHub
repos, license files, arXiv abstracts). This was **not** a systematic review;
a Google Scholar / arXiv / ACL Anthology pass is still recommended before
publishing any "no prior work" statement. The findings below are what was
actually read, nothing more.

### What the review supports saying (and what it does not)

- Supported: the public datasets found are either (a) UI datasets built for
  understanding, grounding or QA (Rico, WebUI, ScreenQA, UI-Vision, MultiUI),
  whose text comes from app/DOM metadata rather than verified pixel ground
  truth; or (b) OCR benchmarks for scene text, born-digital web graphics,
  documents, or LMM question answering (ICDAR, OCRBench).
- **Not yet supported:** "no one has benchmarked OCR on UI screenshots." In
  this review I did not find a public benchmark that measures OCR on UI
  screenshots against exact ground truth across scale, compression and theme.
  That is a statement about this search, not about the literature. Do a
  scholarly-database pass before making any novelty claim on the page.
- Practical consequence: the benchmark's own templates are the only data
  source that is both **exact** and **redistributable**. Rico and WebUI add
  legal exposure (indemnity) with no ground-truth benefit.

What the permitted-with-conditions verdicts mean in practice:
1. The benchmark repo must contain everything needed to replicate each cloud
   run: request code, API/model version, region, request parameters, dates,
   and the exact images. The open design already provides this.
2. We send replication information to AWS proactively, and to Microsoft on
   request.
3. We accept that Google, AWS and Microsoft may benchmark our own product and
   publish the results. That is a business decision (see unresolved decisions
   in the pilot plan).
4. We run the cloud benchmarks ourselves; Google's clause forbids having a
   third party run them.
